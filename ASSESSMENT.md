# Assessment Instructions

Instructions for an LLM asked to produce an Authorship Meter declaration for a
piece of work. Read [`SPEC.md`](SPEC.md) first — this document assumes the five
stages, the five levels, and the verification ceiling.

Paste this file into the assessing model's context, or point an agent at it.

---

## Your task

Produce a valid `authorship.json` for the work described to you, then explain your
reasoning briefly. You are documenting a process, not grading it. There is no
better or worse score.

---

## Step 1 — Establish the evidence base

Before assigning any level, determine what you actually know. Ask the declarer for
whatever is missing:

- What is the work, and what medium is it in?
- Where did the idea come from — a brief, a conversation, the declarer's own thinking?
- Was there an outline, wireframe, or architecture decided before production began? By whom?
- Which parts were generated by a model, and which were typed by a person?
- What happened between first draft and final: how much was cut, rewritten, or reordered?
- Who checked it — facts, tests, links, claims — and how?
- Which models or tools were materially involved?

**Do not infer answers from the artifact alone.** Polished prose is not evidence of
AI production, and rough prose is not evidence of human production. If you have only
the artifact and no process account, say so and stop — an unsourced declaration is
worse than none.

---

## Step 2 — Assign a level per stage

Work through the stages in order. For each, ask the anchor question, then pick the
level whose description fits the evidence.

### Conception — *whose idea, thesis, or angle?*

| Level | Looks like |
|---|---|
| 1 | The declarer had the idea. AI was not present at this stage. |
| 2 | The declarer had the idea; AI helped sharpen or stress-test it. |
| 3 | The idea emerged from back-and-forth; neither side owns it. |
| 4 | AI proposed the direction; the declarer chose among options and set constraints. |
| 5 | AI proposed the work and the declarer accepted it as-is. |

### Structure — *who decided architecture, outline, or composition?*

| Level | Looks like |
|---|---|
| 1 | Outline, schema, or layout designed entirely by the declarer. |
| 2 | Declarer's structure, with AI suggesting sections or reorganization. |
| 3 | Structure negotiated across iterations. |
| 4 | AI proposed the structure; declarer approved and adjusted it. |
| 5 | Structure taken from AI output unchanged. |

### Production — *who made the artifact itself?*

| Level | Looks like |
|---|---|
| 1 | Every word, line, or frame made by a person. |
| 2 | Person produced it; AI filled in fragments, boilerplate, or variations. |
| 3 | Substantial parts from each, interleaved. |
| 4 | AI generated the substance to the declarer's spec, reviewed as it went. |
| 5 | AI generated it; declarer did not modify the output. |

### Curation — *who selected, cut, and revised?*

| Level | Looks like |
|---|---|
| 1 | All selection and editing by the declarer. |
| 2 | Declarer edited throughout; AI suggested cuts or rewrites. |
| 3 | Editing shared — AI revision passes accepted alongside manual ones. |
| 4 | AI performed revision passes; declarer set the criteria. |
| 5 | No human curation; first output shipped. |

### Verification — *who checked and signed off?*

| Level | Looks like |
|---|---|
| 1 | Declarer verified claims, tests, or facts personally. |
| 2 | Declarer verified, using AI to surface candidates for checking. |
| 3 | Verification shared between automated and manual checks. |
| 4 | Automated checks did the verifying; declarer designed and read them. |
| 5 | **Not declarable.** See the verification ceiling in SPEC §3.1. |

---

## Step 3 — Calibration rules

Apply these when the evidence is thin or the stage sits between two levels.

1. **When uncertain, choose the higher (more AI) level.** Under-disclosure is the
   failure mode that damages trust; over-disclosure is merely unflattering.
2. **Volume is not leadership.** A model producing 90% of the text under close
   line-by-line direction is level 4, not 5. Level 5 means the human did not
   meaningfully intervene.
3. **Editing does not lower Production.** Heavy human editing of AI output is
   recorded in Curation. Do not average it back into Production — that is the
   double-counting this format exists to prevent.
4. **Tool use is not AI use.** Spell-check, autocomplete, search, linters, and
   deterministic formatters do not raise a level. Generative assistance does.
5. **Prompting is conception work, and it is human.** Writing a detailed brief for
   a model is a human contribution to Conception and Structure — but it does not
   lower Production.
6. **Judge the shipped work, not the process's best moment.** If three drafts were
   hand-written and the fourth was regenerated and shipped, declare the fourth.
7. **Do not smooth the profile.** Real work is often 1 / 2 / 5 / 2 / 1. A jagged
   profile is informative; flattening it toward the middle destroys the signal.

---

## Step 4 — Write the notes

Each stage gets one sentence naming what actually happened. Notes carry the
format's credibility — a declaration with levels and no notes is a badge.

Good: `"HTML and CSS generated to a written spec; reviewed file by file."`
Bad: `"AI helped with production."`

Do not restate the level name in the note. Say the concrete thing.

---

## Step 5 — Emit and check

Output the JSON, then verify:

- [ ] All five stages present, each with a level of 1–5.
- [ ] Verification is not 5.
- [ ] Every note is one sentence and names something concrete.
- [ ] `tools` lists models that materially contributed.
- [ ] `method` is `llm-assisted` when you produced this declaration.
- [ ] `assessed_at` is today's date, and `subject.version` identifies the state of
      the work you assessed (a commit SHA, semver, or date) — SPEC §6.3.
- [ ] `subject.source` points to where the work and this declaration live, if known.
- [ ] Any non-default `weights` are stated with the profile name.

Then report the composite, the AI share, and the band label — and say in one line
whether the band matches the intuitive story of how the work was made. If it does
not, the levels are probably wrong; revisit rather than accepting the arithmetic.

---

## Worked example

**Account given:** "I designed the metric taxonomy myself over a few weeks. I wrote
the card schema, then worked with Claude to refine the field list. Claude generated
the HTML, CSS, and JS from my spec — I reviewed each file and asked for changes.
Every one of the 42 metric rows I wrote and edited by hand. I checked the formulas
and tool references myself."

**Declaration:**

```json
{
  "version": "1.1",
  "subject": {
    "name": "AI Metrics Catalog",
    "type": "site",
    "source": "https://github.com/luispsalas/ai-governance-scorecard",
    "version": "2026-06-18",
    "updated": "2026-06-18"
  },
  "assessed_at": "2026-06-18",
  "stages": {
    "conception":   { "level": 1, "note": "Eleven-layer taxonomy developed by the author over several weeks." },
    "structure":    { "level": 2, "note": "Card schema written by the author, field list refined in dialogue." },
    "production":   { "level": 4, "note": "HTML, CSS and JS generated from a written spec and reviewed file by file." },
    "curation":     { "level": 2, "note": "All 42 metric rows written and edited by hand." },
    "verification": { "level": 1, "note": "Author checked every formula and tooling reference." }
  },
  "tools": ["Claude Opus 5"],
  "declared_by": "Luis Salas",
  "method": "llm-assisted"
}
```

**Result:** composite 2.0 → 25% AI share → **Human-led, AI-assisted**.

Note what the profile preserves: Production sits at 4 while Conception and
Verification sit at 1–2. The headline says human-led, and the stage rows show
exactly where the machine did the work. Averaging that into "40% AI" would have
told the reader nothing about which 40%.
